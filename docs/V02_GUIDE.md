# ZeroMemory v0.2 使用与回退

## 启动

本次实际服务地址：[http://127.0.0.1:8786](http://127.0.0.1:8786)。若仍在运行，不要重复启动。数据继续使用 `E:\ZeroMemory\data`，不是新库。

```powershell
cd E:\ZeroMemory
.\scripts\Start-ZeroMemory.ps1 -DataHome E:\ZeroMemory\data -Port 8786
# 或
.\.venv\Scripts\python.exe -m zero_memory --home E:\ZeroMemory\data --port 8786
```

服务仅绑定回环地址，无 QQ、B站、手机、SSH 或外部自动写入。无需 LLM 也可使用以下功能；没有启动后台 scheduler。

## 记忆星海

1. 在侧栏打开“记忆星海”，核对“真实数据 · 只读”和当前 scope。现有 56 条摘要全部待审核，管理员可见；普通 MCP 客户端仍只能读已批准记忆。
2. 用线索、类型、状态和日期筛选。每页默认 100 条，API 上限 500 条，按页计算关联，不把全库原文塞进浏览器。敏感记忆默认隐藏，仅本机管理员可显式显示。
3. 星点一一对应原 UUID；点击星点或可访问列表查看来源、证据、审核状态、置信度和原始摘要行号。摘要不是逐字证据，缺失证据会提示“来源待核实”。
4. 关联区分共同主题推导、时间相近、同一来源会话、摘要原文候选以及人工批准的取代/合并关系。推导不证明事实，布局距离也不表示向量相似度。
5. 切换时间线；缺少精确事件时间时明确按提炼时间排列，年份/月的原始精度另行显示，不编造日期。
6. 拖动、缩放按钮、滚轮和方向键可操作星图；列表是触摸及键盘替代。模拟未来和模拟巩固只改变当前视图亮度，假设半衰期不是实际记忆寿命。刷新/重置清除模拟，不改数据库或真实置信度。

## 持续目标与经历

1. 打开“持续目标与经历 → 持续目标”，提出标题、理由、可检查标准和下一步，保存为 proposed。
2. 用户核对后批准为 ready。这一步不触发执行。按“手动运行一次”选择限定的本地只读动作：检索当前 scope 的记忆，或读取自己登记的本地文字资料。
3. 本地资料登记不会访问所填 URL；回执只证明实际读取并校验了提供的文字，不证明网站或资料语义真实。记忆检索默认仅批准项，管理员可明确包含待审核项，敏感项仍排除。
4. 每次运行有稳定 request_id、实际产物版本和 SHA-256、对应 verified/executed 经历；成功后暂停并保存检查点，不自动运行下一步。运行键重试不会重复写入。
5. 需要继续时重新核对环境和授权后恢复为 ready；暂停/取消会保留历史。重启中的 running 会改为 paused，运行标记 interrupted；不会自动重放工具。
6. 手工或模型的事件陈述一律 unverified/executed=false，不能用于伪造成功、兴趣或已完成经验。观察和解释分开保存。
7. 有真实回执的经历可以显式“提议为待审核经验记忆”，统一写入 MemoryBackend 并引用目标/经历/产物；仍需审核，不另造事实库。操作表是目标/经历的权威状态，记忆仅是可审核的召回摘要。

实际研究目标“核对大肥鱼记忆星海的只读接入边界”已保存本地资料回执，目前 paused，等用户核对后决定是否完成。没有为演示自动批准原有记忆，也没有将整个研究目标虚构为已经人工验收。

## 人格与模拟状态

“模拟状态与人格建议”显示精力、好奇、耐心、参与和社交意愿；数值有界，事件可审计，按 15 分钟步长向当前人格基线回归。读取只计算投影，不改写原 `identity/state.json`。新状态按 scope 保存在扩展表，与稳定人格分开。

模型只能提出人格建议。用户在界面核对具体 JSON 补丁及原版本，勾选授权后才应用新身份版本；版本过期会拒绝。原有直接人格编辑入口仍需授权。当前生产人格和头像均未被本次开发修改。情绪、兴趣和方法都不能改变隐私或工具权限。

## 兴趣与方法

- 兴趣只从实际执行且有回执的零自身经历提议，同一来源重复总结不增加独立证据，不当作用户偏好；候选需人工确认。
- 方法必须引用有产物且已经人工验收的已完成目标。填写适用条件、限制和步骤，初始为 candidate。
- 在另一个已批准目标登记一次方法尝试，再执行该目标的本地步骤。目标人工验收完成后回查产物，才能记成功。
- 产物须晚于尝试、版本超过尝试前基线、材料区别于源目标和此前结果。相同目标、旧产物、仅复述同材料均不能刷次数。来源或结果文件损坏会使当前有效计数下降。
- 1 个不同目标成功为 reused_once，至少 2 个为 validated。这里只核对目标、来源、版本和产物条件，不保证任意方法文本在语义上高质量；真实模型研究质量尚未验收。失败、修订和撤销保留历史。

## MCP / API

所有新接口沿用管理员认证、只读/可写 scoped token 和 user/agent/project 隔离。MCP 同一服务器现提供 12 个只读工具，可写模式共 20 个；新增工具只读状态或提出候选，模型不能批准、启动或自报完成目标。

主要接口：

- `GET /v1/observatory/snapshot|timeline`、`POST /v1/observatory/search`、`GET /v1/observatory/memories/{id}`。
- `/v1/activity/goals`、`goals/{id}/run`、`episodes`、`sources`、`artifacts`、`interests`、`methods`、`method-attempts`、`timeline`。
- `/v1/persona-state`、`/v1/persona/events`、`/v1/persona/proposals`。
- `/v1/context` 向不同模型提供同一身份版本、模拟状态、目标和有执行标记的经历；仍只有已批准记忆进入长期记忆上下文。

手动预算为每 scope 每 UTC 日最多 100 次本地只读运行，模型调用和费用为 0。没有定时器、提醒发送或外部执行器，因此未实现调度时间预算、免打扰和费用调度；未来启用网络/外部写入需要单独设计及明确授权。

## 备份、保全与回退

v0.2 备份增加扩展表和 `activity_artifacts/`，恢复仍创建新目录，不覆盖当前数据；兼容不含扩展表的 v0.1 备份。迁移前检测版本和表布局，未知版本拒绝写入。既有非空 v0.1 库第一次启用活动扩展时另做一致性备份，然后只新增表和版本标记，不回填或改写旧记忆。

如需单独关闭功能，启动进程设置：

```powershell
$env:ZERO_OBSERVATORY_ENABLED='false'
$env:ZERO_ACTIVITY_ENABLED='false'
.\scripts\Start-ZeroMemory.ps1 -DataHome E:\ZeroMemory\data -Port 8786
```

先停止旧服务，重新启动才加载这些开关。关闭保留新表和全部证据，核心身份、导入、记忆与备份继续可用。推荐使用开关回退并保留 v0.2 的兼容 Schema；旧版二进制不保证识别 v0.2 的新来源类型。不要删除扩展表、降低 user_version 或把整个库覆盖回旧备份来回退功能。

保全复验（只记录摘要哈希，不输出私密正文）：

```powershell
.\.venv\Scripts\python.exe scripts/baseline_snapshot.py --home data --output output/v02/final-preservation.json --compare output/v02/baseline.json
.\scripts\Test-ZeroMemory.ps1
```

新目标、经历和扩展审计是本轮合法新增；原 56 条记忆、其 UUID/正文/来源/状态/修订、身份/头像文件及原审计前缀必须一致。数据、备份、来源缓存、报告和截图均被 Git 忽略。本次未修改任何全局 MCP 配置或账号设置。
