# 实施决策

| 决策 | 原因和实际边界 |
|---|---|
| 采用 Python 3.12+，本机使用 3.14.4 | 系统默认 python 为 Conda 3.11.13；独立 `.venv` 明确使用已安装的 `C:\Python314\python.exe`，未改系统环境和其他项目 |
| v0.1 默认 SQLite FTS5 | 没有本地模型、Docker、Ollama 或 EverOS 服务；官方服务的记忆提炼依赖模型，完整审核/删除映射未验证。降级为已测可运行实现 |
| 原生 Web 页面取代 React/Vite | 这是本机小型管理界面，使用同源 REST 可以减少构建、依赖和首次运行步骤；仍有完整交互操作 |
| 不下载权重、容器或安装 EverOS | 本机无模型，用户要求无模型也能工作；不需要几十 GB 下载来证明核心持久化 |
| 自动提炼永远进入待审核 | 原文存在只证明证据可追溯，不证明摘要语义正确；不自动把 Assistant 推断变成用户事实 |
| 人工原文引用是独立操作 | 无模型时仍能从导入到审核再到记忆检索；UI 明示这是人工引用而非 LLM 提炼完成 |
| 精确去重 + 相似候选 + 人工合并 | 不自动丢弃近似内容；合并保留所有来源快照，批准后旧记录成为历史；语义相似性目前为字符序列相似度 |
| 冲突使用人工指定 fact_key | 实际验证同一事实键的新旧设备替换与历史保留；未宣称自动发现任意自然语言矛盾 |
| 单一 Zero 身份，多用户/项目记忆隔离 | `zero-001` 是全局身份；客户端令牌限定一个 user/project；MCP 参数不接受任意作用域 |
| MCP 通过 REST，不直接打开数据库 | 统一权限、审核与来源验证。默认只读 5 个工具，开启写入后为 7 个，写工具不能批准或改人格 |
| HTTP 仅本机 | `ZERO_HOST` 只允许回环值；不实现公网部署或反向代理配置。无意开启云端地址会被拒绝 |
| 云端双重授权 | 保存 `allow_cloud=true` 还不够；每批/每轮需要精确上下文预览 hash 和显式 consent；默认没有外网模型请求 |
| 恢复永远创建新目录 | 不覆盖当前数据，也不替用户切换 ZERO_HOME；恢复令牌重新生成，模型默认关闭 |
| 锁定全部依赖 | `uv.lock` 保存实际解析版本，`uv sync --frozen` 可复现；没有创建远程仓库、提交或推送 |

## 环境问题的处理

PowerShell 每次启动可能输出 `InitializeDefaultDrives` 的沙箱警告，但项目读写可用。uv 初次在系统临时目录更新 Windows PE 资源失败；改用项目内 `.cache/tmp`、`.cache/uv` 和 `UV_LINK_MODE=copy` 后完成安装。未修改系统 TEMP、全局依赖或其他工程。

Playwright 通过项目内 npm 缓存使用；Windows 没有 bash，因此使用等价的 `npx --package @playwright/cli playwright-cli` 调用。自动验收中的所有聊天均为合成数据，放在 gitignored `output/` 下。

Windows 虚拟环境 Python 启动器 PID 可能不同于实际解释器/监听 PID。验收服务从 `/health` 读取真实 `process_id`，终止真实服务、验证旧端口关闭，再在同一端口启动新进程，避免仅终止启动器造成的重启误判。正式后台服务状态也记录实际服务 PID。
